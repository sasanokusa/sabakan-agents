# 条件行列の実行経路の確認

Issue #9/#10に向け、CUDA開発runnerのB2固定を撤去し、行ごとのconditionをrun_trialへ渡す。B0は同じ公開入力を読む既存playbook、それ以外は同じモデルcallbackを使う。HTTPのB0は異なる観測契約のため、このrunnerでは起動前に拒否する。

起動前のvalidate_matrixで未知ケース・未知条件・未知観測、非booleanの機構スイッチ、重複したcase/condition/observation/repetition、複数条件があるのに条件を省略した行を拒否する。単一条件の過去計画は互換性を維持する。これは行列の完全性検証の一部であり、計画全組合せの欠落検査や未使用ケース検証はまだ別途必要。

実Dockerの停止サービス開発ケースに固定の公開観測playbookを使って5条件を実行し、すべて復旧を確認した。最初に実際に公開されたToolはB0/B2/A_no_hintsで14件、B1/A_no_stagingで18件。全入力と結果はevaluation/condition-wiring-controls-20260908.jsonに保存した。モデルの機構効果比較ではなく、実行経路の対照である。短い復旧経路のため反復観測ヒントの到達性はこの対照では証明していない。
